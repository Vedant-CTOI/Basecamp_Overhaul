# Design Canon — References

The principles and hard-won rules that govern every design decision in this repo,
pulled from the Prism/Basecamp platform project so the build team holds the same
canon as the original deployments. Read top to bottom before designing or
reviewing any surface.

| Doc | What it holds | Authority |
|---|---|---|
| [`philosophy.md`](philosophy.md) | North star + six product principles (universal core vs idea-gen manifestation). The codebase is downstream of this worldview. | Highest — every feature serves a principle |
| [`ux-rules.md`](ux-rules.md) | Hard rules from live rooms: projector readability, click-not-hover, mobile voting, error copy, motion, AI conduct | Binding on all surfaces |
| [`../ogilvy-showcase-direction.md`](../ogilvy-showcase-direction.md) | This edition's design contract: palette, type, registers, signature elements, settled rulings (Rounds 1–3) | Binding on this branch |
| [`craft-moments.md`](craft-moments.md) | Taxonomy of memorable moments (opening, transition, peak, ambient, closing) and how to budget for them | Design vocabulary |
| [`v2-interaction-direction.md`](v2-interaction-direction.md) | Interaction direction: coaches on the field, structured options over chat, group-oriented AI | Directional |
| [`client-deliverable-framing.md`](client-deliverable-framing.md) | Report structure: cross-team patterns first, never team-by-team inventories | Binding on the Edition/report |

Two rules of use:

1. **Conflicts resolve upward.** If a surface decision contradicts `philosophy.md`
   or `ux-rules.md`, the surface is wrong — or the conflict goes to the product
   owner, never silently decided.
2. **Settled rulings stay settled.** `ogilvy-showcase-direction.md` records
   decisions with dates. Reopen one only with a genuinely new argument, not a
   fresh pair of eyes.
